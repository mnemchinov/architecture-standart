# ADR-002: Передача ставок в кол-центр

## Название задачи
Автоматизация передачи ставок по депозитам в систему кол-центра

## Автор
Архитектор системы

## Дата
2026-02-17

---

## Статус
Предложено

## Контекст

### Проблема

В текущем процессе менеджеры кол-центра не имеют доступа к актуальным ставкам по депозитам при работе с клиентами по телефону. Это создаёт следующие проблемы:

1. **Задержки в обслуживании:** Менеджер не может сразу озвучить ставку клиенту, требуется дополнительное время на запрос
2. **Неполная информация:** Клиент не получает полной информации о продуктах во время звонка
3. **Риск потери клиента:** Клиент может обратиться в другой банк, если не получит оперативную информацию
4. **Неравномерная нагрузка:** Заявки из кол-центра передаются в бэк-офис для расчёта ставок, что увеличивает нагрузку

### Текущий процесс

1. Клиент звонит в кол-центр для уточнения условий депозита
2. Менеджер кол-центра создаёт обращение в своей системе
3. Обращение передаётся в АБС
4. Сотрудники бэк-офиса обрабатывают заявку в АБС для определения ставки
5. Если ставка определена, сотрудник обрабатывает заявку в АБС и указывает ставку
6. АБС отправляет СМС-оповещение клиенту о том, что он может получить депозит под указанную ставку
7. Клиент должен прийти в отделение для открытия депозита

### Требования бизнеса

- Менеджеры кол-центра должны иметь доступ к актуальным ставкам по депозитам в реальном времени
- Ставки должны быть доступны для:
  - Общих ставок (базовые ставки для всех клиентов)
  - Персонализированных ставок (для существующих клиентов банка)
- Менеджер должен иметь возможность запросить персонализированную ставку для конкретного клиента
- Решение должно быть интегрировано с существующими системами (АБС, система кол-центра)
- Должна обеспечиваться безопасность передачи данных (шифрование)

### Ограничения

- Использовать существующие технологии (MS SQL, Oracle, Java/Spring Boot)
- Минимизировать изменения в АБС (подрядчик)
- Соблюдать требования безопасности (шифрование трафика)
- Обеспечить быстрый отклик (менее 100 мс для справочных данных)

### Ключевые компоненты

#### 1. Модуль в Системе кол-центра

**Назначение:** Расширение функционала системы кол-центра для работы со ставками

**Функции:**
- Отображение общих ставок по депозитам в приложении менеджера
- Форма запроса персонализированной ставки (ввод номера телефона или ID клиента)
- Отображение персонализированной ставки
- Создание заявки на депозит после согласования ставки

**Технология:** Java/Spring Boot (расширение существующей системы)

#### 2. API в Системе кол-центра

**Назначение:** API для получения ставок

**Функции:**
- `GET /api/rates/deposits` — получение общих ставок по депозитам
- `GET /api/rates/deposits/personalized?clientId={id}` — запрос персонализированной ставки
- `POST /api/deposits/applications` — создание заявки на депозит

**Технология:** Java/Spring Boot (REST API)

#### 3. API Gateway (расширение)

**Назначение:** Маршрутизация запросов и кэширование ставок

**Функции:**
- Маршрутизация запросов от системы кол-центра к Сервису ставок или АБС
- Кэширование общих ставок (TTL — 5 минут) для быстрого отклика
- Шифрование трафика (TLS)

**Технология:** ASP.NET Core / Node.js (расширение существующего API Gateway)

#### 4. Сервис ставок (расширение)

**Назначение:** Расчёт и предоставление ставок

**Функции:**
- Предоставление общих ставок по депозитам
- Расчёт персонализированной ставки для клиента на основе:
  - Истории клиента
  - Объёма средств на счетах
  - Продуктов, используемых клиентом
- Хранение ставок в БД

**Технология:** Java/Spring Boot / Node.js (расширение существующего сервиса)

#### 5. Модуль ставок в АБС (расширение)

**Назначение:** Интеграция с Сервисом ставок

**Функции:**
- Получение общих ставок из Сервиса ставок
- Запрос персонализированной ставки в Сервисе ставок
- Хранение ставок в БД АБС (для кэширования)

**Технология:** Delphi (расширение существующей АБС)

### Потоки данных

#### Поток 1: Получение общих ставок (с кэшированием)
1. Менеджер кол-центра → Система кол-центра: запрос общих ставок
2. Система кол-центра → API Gateway: запрос общих ставок
3. API Gateway: проверка кэша
   - Если ставка в кэше — возврат из кэша
   - Если нет — запрос в Сервис ставок
4. API Gateway → Сервис ставок: запрос общих ставок
5. Сервис ставок → API Gateway: возврат ставок
6. API Gateway: сохранение в кэш (TTL — 5 минут)
7. API Gateway → Система кол-центра: возврат ставок
8. Система кол-центра → Менеджер: отображение ставок

#### Поток 2: Запрос персонализированной ставки
1. Менеджер кол-центра → Система кол-центра: ввод номера телефона/ID клиента
2. Система кол-центра → API Gateway: запрос персонализированной ставки
3. API Gateway → АБС: запрос ставки для клиента
4. АБС → Сервис ставок: запрос расчёта персонализированной ставки
5. Сервис ставок → АБС: возврат ставки
6. АБС → API Gateway: возврат ставки
7. API Gateway → Система кол-центра: возврат ставки
8. Система кол-центра → Менеджер: отображение ставки

#### Поток 3: Создание заявки на депозит
1. Менеджер кол-центра → Система кол-центра: создание заявки
2. Система кол-центра → API Gateway: передача заявки
3. API Gateway → АБС: создание заявки на депозит
4. АБС → Менеджер бэк-офиса: уведомление о новой заявке

## Альтернативы

### Альтернатива 1: Прямое подключение системы кол-центра к АБС

**Описание:**
Подключить систему кол-центра напрямую к АБС для получения ставок.

**Преимущества:**
- Проще реализация
- Меньше компонентов

**Недостатки:**
- Перегрузка АБС
- Нет кэширования
- Зависимость от подрядчика АБС

**Решение:** Отклонено — противоречит требованию минимизации нагрузки на АБС

### Альтернатива 2: Хранение ставок в БД системы кол-центра

**Описание:**
Периодически синхронизировать ставки в БД системы кол-центра.

**Преимущества:**
- Максимальная скорость (локальная БД)
- Независимость от внешних систем

**Недостатки:**
- Задержка синхронизации (ставки могут быть неактуальными)
- Дублирование данных
- Сложность поддержки персонализированных ставок

**Решение:** Отклонено — не обеспечивает актуальность ставок в реальном времени

## Недостатки, ограничения, риски

### Недостатки выбранного решения

1. **Дополнительная сложность:** API Gateway как промежуточный слой
2. **Зависимость от кэша:** При сбое кэша увеличивается нагрузка на Сервис ставок
3. **Изменения в АБС:** Требуется расширение модуля ставок

### Ограничения

1. **Персонализация:** Персонализированные ставки доступны только для существующих клиентов
2. **Производительность:** При большом количестве запросов может потребоваться масштабирование API Gateway
3. **Синхронизация:** Требуется синхронизация ставок между Сервисом ставок и АБС

### Риски

| Риск | Вероятность | Влияние | Митигация |
|:-:|:-:|:-:|:-|
| Задержки при получении ставок | Низкая | Среднее | Кэширование в API Gateway |
| Некорректный расчёт персонализированной ставки | Низкая | Высокое | Тестирование, ручной контроль |
| Перегрузка Сервиса ставок | Средняя | Среднее | Масштабирование, мониторинг |
| Проблемы с интеграцией АБС | Средняя | Среднее | Тестирование интеграции, работа с подрядчиком |

## Заключение

Предложенное решение позволяет автоматизировать передачу ставок в кол-центр, что значительно улучшит качество обслуживания клиентов и снизит нагрузку на бэк-офис.

Ключевые преимущества:
- Менеджеры кол-центра имеют доступ к актуальным ставкам в реальном времени
- Возможность запроса персонализированных ставок для существующих клиентов
- Кэширование для быстрого отклика
- Шифрование трафика для безопасности
- Минимальные изменения в АБС

Срок реализации: ~12 недель (3 месяца) при команде из 3 разработчиков + подрядчик АБС.
