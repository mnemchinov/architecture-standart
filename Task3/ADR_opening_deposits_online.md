# ADR-001: Открытие депозитов онлайн — MVP

## Название задачи
Открытие депозитов онлайн — архитектурное решение для MVP

## Автор
Архитектор системы

## Дата
2026-02-17

---

## Статус
Предложено

## Контекст

Банк «Стандарт» планирует цифровую трансформацию для привлечения молодых клиентов. Ключевая задача — обеспечить возможность открытия депозитов и накопительных счетов через онлайн-каналы (сайт и интернет-банк).

### Текущая ситуация

**Существующие проблемы:**
1. Депозиты можно открыть только в отделении — задействованы фронт-офис и бэк-офис
2. Расчёт ставок производится вручную в Excel-файлах отделом кредитования
3. Ставки передаются в бэк-офис ежедневно по email
4. Онлайн-каналы (сайт, интернет-банк) имеют ограниченный функционал
5. Интернет-банк подключён напрямую к БД АБС, что создаёт риски безопасности и перегрузки
6. База данных АБС уже перегружена

**Требования бизнеса:**
- MVP: возможность подать заявку на депозит через сайт и интернет-банк
- Персонализированные ставки для существующих клиентов в интернет-банке
- Подтверждение операций СМС-кодом
- Обработка заявки менеджером бэк-офиса в АБС
- СМС-уведомления клиенту о ставке и открытии депозита
- Быстрый отклик (миллисекунды)
- Доступность 24/7 (99.9%)
- Шифрование трафика между системами

**Ограничения:**
- Использовать существующие технологии (MS SQL, Oracle)
- Избегать прямой работы интернет-банка с API АБС
- Функционал СМС реализовать силами команды банка (без подрядчика АБС)
- Текущая версия платформы интернет-банка несовместима с Kafka

## Решение

### Общая архитектура

└─────────────────────────────────────────────────────────────────────┘

### Ключевые компоненты

#### 1. API Gateway
**Назначение:** Промежуточный слой между онлайн-каналами и АБС

**Функции:**
- Маршрутизация запросов от сайта, интернет-банка, кол-центра к соответствующим сервисам
- Аутентификация и авторизация запросов
- Шифрование/дешифрование трафика (TLS)
- Балансировка нагрузки
- Кэширование справочных данных (ставки, список депозитов) для быстрого отклика

**Технология:** ASP.NET Core (совместим с текущим интернет-банком) или Node.js/Express (есть экспертиза в банке)

#### 2. Сервис ставок (Rates Service)
**Назначение:** Автоматический расчёт и хранение ставок по депозитам

**Функции:**
- Автоматический расчёт ставок на основе:
  - Ставки рефинансирования ЦБ
  - Уровня кредитного риска банка
  - Текущего объёма кредитов/депозитов
- Хранение ставок в БД (Oracle или MS SQL)
- Предоставление API для получения актуальных ставок
- Расчёт персонализированных ставок для существующих клиентов

**Технология:** Java/Spring Boot (есть экспертиза в команде АБС) или Node.js/Express

**База данных:** Oracle (для интеграции с АБС) или MS SQL (совместим с интернет-банком)

#### 3. Модуль депозитов в АБС
**Назначение:** Обработка заявок на открытие депозитов

**Функции:**
- Создание заявки на депозит
- Хранение заявок в БД АБС
- Рабочее место менеджера бэк-офиса для обработки заявок
- Подтверждение условий депозита и ставки
- Открытие депозита

**Технология:** Расширение существующей АБС (Delphi/Oracle)

#### 4. Модуль ставок в АБС
**Назначение:** Управление ставками по депозитам

**Функции:**
- Хранение ставок по депозитам
- Редактирование ставок сотрудниками бэк-офиса депозитов и кредитов
- Интеграция с Сервисом ставок для автоматического расчёта

**Технология:** Расширение существующей АБС (Delphi/Oracle)

#### 5. Модуль СМС в АБС
**Назначение:** Отправка СМС-уведомлений клиентам

**Функции:**
- Генерация СМС-кода для подтверждения операции
- Отправка СМС о подтверждённой ставке
- Отправка СМС об открытии депозита

**Технология:** Разработка силами команды банка (Java/Spring Boot или Node.js)

**Интеграция:** СМС-шлюз телеком-оператора (существующий)

#### 6. Сайт
**Назначение:** Подача заявок на депозит новыми клиентами

**Функции:**
- Отображение списка депозитов с актуальными ставками
- Форма подачи заявки (Ф.И.О., номер телефона)
- Шифрование передаваемых данных

**Технология:** Расширение существующего сайта (PHP/React.js)

#### 7. Интернет-банк
**Назначение:** Открытие депозитов существующими клиентами

**Функции:**
- Отображение списка депозитов с персонализированными ставками
- Выбор депозита, счёта и суммы
- Подача заявки на депозит
- Ввод СМС-кода для подтверждения
- Шифрование передаваемых данных

**Технология:** Расширение существующего интернет-банка (ASP.NET MVC 4.5, MS SQL)

#### 8. Система кол-центра
**Назначение:** Обработка заявок с сайта и звонков клиентов

**Функции:**
- Получение заявок с сайта через API Gateway
- Отображение заявок менеджерам
- Создание обращения в АБС
- Запрос персонализированной ставки для клиента

**Технология:** Расширение существующей системы (Java/Spring Boot, PostgreSQL)

### Потоки данных

#### Поток 1: Просмотр депозитов на сайте
1. Сайт → API Gateway: запрос списка депозитов и ставок
2. API Gateway → Сервис ставок: запрос актуальных ставок (с кэшированием)
3. API Gateway → Сайт: возврат списка депозитов и ставок
4. Сайт → Клиент: отображение данных

#### Поток 2: Подача заявки на депозит на сайте
1. Клиент → Сайт: ввод данных (Ф.И.О., телефон)
2. Сайт → API Gateway: передача заявки (с шифрованием)
3. API Gateway → Система кол-центра: создание заявки
4. Система кол-центра → АБС: передача заявки для хранения
5. АБС → СМС-шлюз → Клиент: СМС-уведомление о получении заявки (опционально)

#### Поток 3: Обработка заявки менеджером кол-центра
1. Менеджер → Система кол-центра: просмотр заявки
2. Менеджер → Система кол-центра: запрос персонализированной ставки
3. Система кол-центра → АБС: запрос ставки
4. АБС → Система кол-центра: возврат ставки
5. Менеджер → Клиент: звонок для согласования условий

#### Поток 4: Просмотр депозитов в интернет-банке
1. Клиент → Интернет-банк: авторизация
2. Интернет-банк → API Gateway: запрос депозитов и персонализированных ставок
3. API Gateway → Сервис ставок: запрос ставок для клиента
4. API Gateway → Интернет-банк: возврат данных
5. Интернет-банк → Клиент: отображение депозитов

#### Поток 5: Подача заявки на депозит в интернет-банке
1. Клиент → Интернет-банк: выбор депозита, счёта, суммы
2. Интернет-банк → API Gateway: создание заявки (с шифрованием)
3. API Gateway → АБС: создание заявки на депозит
4. АБС → Модуль СМС → СМС-шлюз → Клиент: СМС-код для подтверждения

#### Поток 6: Подтверждение СМС-кодом
1. Клиент → Интернет-банк: ввод СМС-кода
2. Интернет-банк → API Gateway: проверка кода
3. API Gateway → АБС: подтверждение заявки
4. АБС → Менеджер бэк-офиса: уведомление о новой заявке

#### Поток 7: Обработка заявки менеджером бэк-офиса
1. Менеджер → АБС: просмотр заявки
2. Менеджер → АБС: подтверждение условий и ставки
3. АБС → Модуль СМС → СМС-шлюз → Клиент: СМС о подтверждённой ставке
4. Менеджер → АБС: открытие депозита
5. АБС → Модуль СМС → СМС-шлюз → Клиент: СМС об открытии депозита

### Выбор технологий

**Почему ASP.NET Core / Node.js для API Gateway:**
- Совместимость с текущим интернет-банком (ASP.NET)
- Экспертиза в банке (Java/Spring Boot в АБС)
- Возможность масштабирования в будущем
- Поддержка шифрования TLS

**Почему Java/Spring Boot для Сервиса ставок:**
- Экспертиза в команде АБС
- Совместимость с Oracle
- Возможность интеграции с АБС

**Почему MS SQL для сервисов:**
- Совместимость с интернет-банком
- Экспертиза в банке

**Почему Delphi/Oracle для АБС:**
- Существующая система
- Поддержка подрядчиком
- Возможность расширения

## Альтернативы

### Альтернатива 1: Прямая интеграция онлайн-каналов с АБС

**Описание:**
Подключить сайт и интернет-банк напрямую к API АБС без промежуточного слоя.

**Преимущества:**
- Проще реализация
- Меньше компонентов

**Недостатки:**
- Перегрузка БД АБС (уже перегружена)
- Риски безопасности
- Зависимость от подрядчика АБС
- Сложность масштабирования

**Решение:** Отклонено — противоречит требованию NFR-6

### Альтернатива 2: Использование Kafka для очередей сообщений

**Описание:**
Использовать Kafka для асинхронной передачи сообщений между системами.

**Преимущества:**
- Масштабируемость
- Надёжность
- Отказоустойчивость

**Недостатки:**
- Текущая версия платформы интернет-банка несовместима с Kafka
- Дополнительная сложность
- Требует обучения команды

**Решение:** Отклонено для MVP, может быть рассмотрено в будущем при переходе на микросервисную архитектуру

### Альтернатива 3: Разработка нового модуля СМС подрядчиком АБС

**Описание:**
Поручить разработку модуля СМС подрядчику АБС.

**Преимущества:**
- Интеграция с АБС

**Недостатки:**
- Зависимость от подрядчика
- Дополнительные затраты
- Риск задержек

**Решение:** Отклонено — требование разработать силами команды банка

## Недостатки, ограничения, риски

### Недостатки выбранного решения

1. **Дополнительный слой (API Gateway):** Усложняет архитектуру, требует поддержки
2. **Дублирование функционала:** Сервис ставок и модуль ставок в АБС дублируют часть логики
3. **Миграция данных:** Требуется миграция ставок из Excel в БД
4. **Обучение команды:** Новые технологии (ASP.NET Core, Spring Boot)

### Ограничения

1. **MVP-подход:** Заявки обрабатываются менеджером бэк-офиса, не полностью автоматически
2. **Регуляторные требования:** Новые клиенты должны проходить идентификацию в отделении
3. **Совместимость:** Текущая платформа интернет-банка ограничивает использование Kafka
4. **Ресурсы:** Ограниченная команда разработки

### Риски

| Риск | Вероятность | Влияние | Митигация |
|:-:|:-:|:-:|:-|
| Перегрузка АБС | Средняя | Высокое | API Gateway с кэшированием, мониторинг нагрузки |
| Задержки с СМС | Низкая | Среднее | Использование надёжного СМС-шлюза, резервные каналы |
| Ошибки в расчёте ставок | Низкая | Высокое | Тестирование, ручной контроль на этапе внедрения |
| Проблемы с безопасностью | Средняя | Высокое | Шифрование TLS, аудит безопасности |
| Задержки разработки | Средняя | Среднее | Поэтапная реализация, приоритизация MVP |

## План реализации

### Этап 1: Инфраструктура и базовые сервисы
1. Разработка API Gateway
2. Разработка Сервиса ставок
3. Миграция ставок из Excel в БД
4. Настройка шифрования TLS

### Этап 2: Интеграция с АБС
1. Расширение АБС (модуль депозитов, ставок, СМС)
2. Интеграция API Gateway с АБС
3. Интеграция Сервиса ставок с АБС

### Этап 3: Онлайн-каналы
1. Расширение сайта (просмотр депозитов, подача заявки)
2. Расширение интернет-банка (просмотр депозитов, подача заявки, СМС-подтверждение)
