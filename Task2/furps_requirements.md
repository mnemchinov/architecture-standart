| UC-5 | Клиент, Сотрудник отделения | Идентификация в отделении | Клиент приходит в отделение для идентификации и открытия депозита (требование регулятора) |

| UC-9 | Менеджер бэк-офиса, АБС | Обработка заявки в АБС | Менеджер бэк-офиса получает заявку, подтверждает условия депозита и ставку в АБС |
| UC-10 | АБС, СМС-шлюз, Клиент | СМС-уведомление о ставке | Клиент получает СМС-уведомление о подтверждённой ставке по депозиту |

| UC-13 | Сотрудник бэк-офиса депозитов, АБС | Работа со ставками (депозиты) | Сотрудники бэк-офиса депозитов могут просматривать и редактировать ставки в АБС |
| UC-14 | Сотрудник бэк-офиса кредитов, АБС | Работа со ставками (кредиты) | Сотрудники бэк-офиса кредитов могут просматривать и редактировать ставки в АБС |

| UC-17 | Интернет-банк, АБС | Создание заявки на депозит | Интернет-банк создаёт заявку на депозит в АБС |
| UC-18 | Система кол-центра, АБС | Запрос персонализированной ставки | Система кол-центра запрашивает персонализированную ставку для клиента в АБС |

## Нефункциональные требования

| № | Требование |
|:-:|:-|
| NFR-1 | **Производительность (Performance):** Отклик по транзакционным операциям — менее 500 мс. Справочные данные должны загружаться менее чем за 100 мс |
| NFR-2 | **Доступность (Reliability):** Все сервисы должны работать 24/7 и быть доступны в 99.9% случаев |
| NFR-3 | **Надёжность (Reliability):** В случае сбоев в ЦОД сервисы интернет-банка должны быть доступны и выдерживать нагрузку до 100 одновременных пользователей |
| NFR-4 | **Поддержка (Supportability):** Использовать технологии, которые уже есть в банке (MS SQL, Oracle). Новые технологии должны быть совместимы с существующими платформами разработки |
| NFR-5 | **Безопасность (Security):** Данные при передаче между системами должны быть защищены механизмом шифрования трафика (TLS 1.3) |
| NFR-6 | **Масштабируемость:** Избегать прямой работы интернет-банка с API АБС в новом процессе для предотвращения перегрузки БД. Нагрузка на АБС не должна превышать 10 запросов/сек |
| NFR-7 | **Экспертиза:** Желательно, чтобы внутри банка уже была экспертиза в используемых технологиях (на уровне языков программирования) |
| NFR-8 | **Очереди сообщений:** При необходимости использовать очереди сообщений (Kafka на перспективу) |
| NFR-9 | **Дизайн (Usability):** Интерфейс работы должен быть максимально удобным для клиента. Соблюдать систему дизайна компании (цвета, брендированные элементы) |
| NFR-10 | **Документация:** Предусмотреть разработку документации для дальнейшего расширения системы |
| NFR-11 | **Совместимость (Portability):** Текущая версия платформы интернет-банка несовместима с Kafka. При необходимости перехода на микросервисную архитектуру учитывать это ограничение |
| NFR-12 | **Регуляторные требования:** Банки не могут принимать новых клиентов без личной проверки документов. Онлайн-подача заявки не заменяет идентификацию в отделении |

## Архитектурно значимые требования

| № | Требование |
|:-:|:-|
| AFR-1 | Создать промежуточный слой между онлайн-каналами и АБС для разгрузки БД АБС |
| AFR-2 | Перенести расчёт ставок из Excel-файлов в АБС для автоматизации и исключения ручных ошибок |
| AFR-3 | Реализовать функционал работы с СМС силами команды разработки банка (без доработки подрядчиком АБС) |
| AFR-4 | Предусмотреть возможность перевода интернет-банка на микросервисную архитектуру в рамках задачи открытия депозитов |
| AFR-5 | Обеспечить персонализированные ставки для существующих клиентов в интернет-банке |
| AFR-6 | Интегрировать систему кол-центра с АБС для автоматической передачи заявок и получения ставок |
| AFR-7 | Обеспечить передачу ставок в кол-центр для информирования клиентов по телефону |

## Примечания

1. **MVP-подход:** В рамках MVP предполагается, что заявку на открытие депозита обработает менеджер в бэк-офисе. Полная автоматизация возможна в будущем.
2. **Ставки:** Текущий процесс со ставками в Excel-файлах неэффективен и должен быть заменён на автоматический расчёт в АБС.
3. **Персонализация:** Персонализированные ставки для существующих клиентов — конкурентное преимущество банка.
4. **Безопасность:** Шифрование трафика обязательно для всех систем, передающих чувствительную информацию.
5. **Масштабируемость:** Прямая работа с БД АБС недопустима из-за её перегрузки. Необходим промежуточный слой.
